# Error pages move to https://zigbox.org/errors/

*Decided 2026-11-21, by the owner.*

Supersedes the error-page address of
[2026-11-04-errors-on-org-site.md](2026-11-04-errors-on-org-site.md) (`/errors/box/`), which was
never applied to the binaries: 0.3.x to 0.5.x print `https://zigbox.github.io/zigbox/errors/`.

## Decision

- From 0.6.0, every diagnostic's `docs` line, its JSON `docs` field and `zbx explain` name
  `https://zigbox.org/errors/<code>.html`: `constants.docs_url_base` is
  `https://zigbox.org/errors/`, and the generated pages' canonical link (`errors_site.zig`
  `site_url`) is `https://zigbox.org/`.
- The goldens and the VM demo expectations that print the address were rewritten with the
  constant. The repository has no golden-update mode (see
  [2026-11-09-m8-slice12-credentials.md](2026-11-09-m8-slice12-credentials.md)), so the old base
  was replaced in them as one substitution and `zig build test` confirmed each byte for byte
  against what the code now renders. The bundle manifest goldens
  (`src/testdata/bundle/manifest*.txt`) give `doctor.json`'s size, which is 26 bytes smaller (two
  links, 13 bytes each); the number is the one the test found. `site/errors/` was regenerated by
  `zig build errors-site`.
  Recordings of real runs (`src/testing/vm/recorded_m2b.zig`, the captured `real_e0213` in
  `agent_json_m6b.zig`), release evidence, demo documents, briefs, older release notes and
  decisions keep the address they recorded.
- The release's `verify` job checks that `https://zigbox.org/errors/E0001.html` answers 200
  (following zigbox.org's redirect from `.html` to the bare path) after the site deploy.

## Old links

0.5.x binaries print `https://zigbox.github.io/zigbox/errors/<code>.html`, which this
repository's Pages workflow (`pages.yml`, all of `site/`) still serves. It keeps doing so for as
long as those binaries are in use; `pages.yml` is unchanged.

## Publishing (open)

The pages reach zigbox.org only through `ZigboxOrg/website`, whose deploy copies `site/errors/`
from this repository's `main` into `/errors/box/` today. Serving them at `/errors/` needs a change
to that deploy, or a release step that writes them into that repository; which one is the
owner's to choose. `zigbox.org/errors/index.html` is the website's own index of Zigbox's and
Zigcube's codes, so the generated `site/errors/index.html` must not replace it.
