# 0.6.0: `--lazy` is on in every build, and E0004 stays

*Decided 2026-11-21, by the slice (0.6.0 plan, lane A item A4), following earlier decisions.
Nothing new was chosen.*

Item A4 of [2026-11-19-0.6.0-plan.md](2026-11-19-0.6.0-plan.md) asked for the `lazy_start` build
option and the E0004 refusal of `zbx run --lazy` to go, with the goldens, help and errors site
brought along. The work was already on `main` when A4 started: S2 slice 6 (2104c022) undid the
0.5.2 dormancy, and [2026-11-18-0.6.0-lazy-start-gate.md](2026-11-18-0.6.0-lazy-start-gate.md)
recorded it. A4 checked each part and found:

- **The build option is gone.** `build.zig` has no `lazy_start` option and no
  `lazy_start_options`; `src/cli.zig` has no `lazy_not_yet`. The shipped `zbx`, the unit tests,
  the fuzzers and every VM demo build the same binary.
- **`demo-s2` and `demo-s2-lazy` stay two steps.** `demo-s2-lazy` (S2 slice 4's check, from the
  store) no longer has a `zbx` of its own, so there was nothing to fold; it tests a different path
  from `demo-s2` (from a throttled registry) and keeps its own step, its own `vm.yml` name
  (`s2lazy`) and its place in `vm/all-*`. No CI path changed.
- **Help, goldens, errors site.** `zbx help run` lists `--lazy` with no release caveat. E1208's
  golden is a `run --lazy --rootfs` line again and E0555's carries the writer 2 digest; the
  "lazy start arrives in 0.6.0" text of E1207 and E1208 was only ever on the 0.5.2 and 0.5.3
  release branches, never on `main`. `zig build errors-site-check` passes on this commit.
- **E0004 is not retired.** It is the general "unknown option" code, raised by `unknown_option`
  in `src/cli.zig` for every option zbx does not know, and by several commands' own parsers. The
  0.5.2 refusal borrowed it ("No new code was registered",
  [2026-11-16-0.5.2-s2-dormant.md](2026-11-16-0.5.2-s2-dormant.md)); removing that one raise
  leaves the code with many raisers, and its registry text never mentioned `--lazy`. So the
  question of retiring it does not arise, and nothing in the registry changed.
- **`--lazy` stays opt-in.** "On" means every build has it, not that a plain `zbx run` starts
  lazily. That default is the owner's later call (the S2 brief's owner's call 5), and this item
  does not change it.

What A4 changed: one stale test comment in `src/google/pull_tests.zig` that still called
`run --lazy` dormant in a release build, and this file. README's S2 row still says S2 is
"unreachable unless built with `-Dlazy-start`"; README and the site are the supervisor's to update
with item A5.
